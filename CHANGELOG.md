### Fixed

- The transport no longer resolves a deadline-exceeded exchange as a success (U-007, spec §7.2; decision D-072): `providerFetch`'s body-read loop treated a `done` stream resolution as success without consulting the §7.2 deadline — D-042's "signal state is the classification authority" rule was enforced only on the rejection paths. Under a rare abort-vs-read race on a loaded 2-core runner (CI run 41162981449, matrix job `test (22.13.0)`, "times out while reading a slow body"), undici closed the aborted trickle body as `done`, so an exchange that had blown its 120 ms deadline resolved as `{ status: 200, … }`, possibly truncated — which the outcome mapping would have recorded as a parse failure (`Format changed`) instead of the timeout (`Unreachable`) it was. Both success returns — the read loop's `done` exit and the bodiless-2xx return — now verify the deadline and caller signal state first, through one shared classifier whose deadline-wins precedence now lives (and is test-pinned) in a single place: a fired deadline yields `TransportTimeoutError`, a fired caller signal `TransportAbortError`. Delivered non-2xx, wrong-content-type, and over-cap responses keep their classifications even when a signal raced them — an arrived status is more actionable, and §7.2's 429 and 401/403 rows must not collapse into the retryable timeout row on a timer race. The lost race is pinned deterministically socket-free through the injected `fetchImpl` (a fetch double that resolves only after the composed signal aborted): done-resolving bodies (empty and truncated) and bodiless 2xx responses map to the timeout/abort errors, a clean completion still succeeds, both-fired keeps the deadline winning, and the observation paths keep their classes; the real-socket suites are unchanged and green.
- Non-finite configuration numbers are named truthfully in field-level errors (task 113, spec §9.2; decision D-071): a numeric setting arriving as `Infinity`, `-Infinity`, or `NaN` — reachable from a hand-edited file through an out-of-range JSON literal such as `1e400`, which strict `JSON.parse` yields as `Infinity` — was already rejected by both validation engines (TypeBox and the Ajv-compiled contract exclude non-finite doubles from the `number` type, verified on the pinned runtime), but the rendered problem contradicted itself (`multiplier: expected a number, got a number`). Type errors now say `got a non-finite number` for every numeric setting, remaining value-free per §15.4; task 067's pinned expectation for its env digit-string route into `server.port` is updated to the repaired wording.
- Z.ai metric derivations stay finite (task 101, spec §8.4; decision D-057): an arithmetic derivation (`remaining = limit − used`, `used = limit − remaining`, `limit = used + remaining`, `percentUsed = 100 · used / limit`) or the `windowSeconds = number × 3600` scaling whose result overflows IEEE-754 finiteness (extreme magnitudes; zero allowances in a quotient) now leaves the field absent and unlisted instead of emitting `Infinity`/`NaN` values the shared §8.4 snapshot invariants reject — the supplied values survive and the metric stays valid. Zero-allowance behavior from task 100's review is unchanged: result-finiteness subsumes the old `limit !== 0` guard.
- The rolling mutation-report issue no longer shows a self-contradictory 0% report: the renderer (extracted to `scripts/render-mutation-report.mjs`, now callable by the workflow and by hand against any artifact JSON) normalizes Stryker's PascalCase mutant statuses, so the score, per-file table, and survived triage list match the report JSON, with runtime/compile-error mutants surfaced as counts and files (U-005, decision D-054).
- The daily mutation workflow now bootstraps its `mutation-report` label idempotently before first use: `gh issue create --label` requires the label to already exist and cannot create it, which failed the workflow's validation run at the issue-upsert step (U-004).
- `npm audit` restored after the npm registry retired the quick-audit endpoint: the dev image and CI now pin npm 11 (bulk advisory endpoint) while Node stays at the 22.13.0 minimum.
