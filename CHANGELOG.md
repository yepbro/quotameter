Pinned contract: primary epoch order with the D-090 exact-sign ladder, an ascending finite-`number` tie-break (domain deliberately "any finite number" — an epoch at the services site, an integer counter at the storage site; the family claims neither identity), and non-finite `NaN`/`±Infinity` throwing a `TypeError` per key role on every invocation — both keys of both items validated eagerly, primary pair first, so rejection never depends on where a sort happens to stop comparing; equal keys yield `0`, preserving the stable-sort input order the peak-hours suite pins. - A component whose rollback stop rejected is no longer leaked with no retry route (U-018, spec §5.6, §17.1; decision D-088): `QuotameterApp`'s startup rollback stops the started components best-effort and swallows per-component stop failures so the original startup error can propagate — which left a component whose stop rejected (an open SQLite handle, a listener, a timer) holding its resource forever: the state became `'failed'` and `stop()` was documented as a no-op from there, contradicting `start()`'s own "leaves nothing running" contract and letting a leaked handle keep the process alive after `runServer` had returned its failure code.
